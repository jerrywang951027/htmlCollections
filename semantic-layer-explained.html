01 / Short answer

Both descriptions are incomplete.

A semantic layer includes data-dictionary information and groups data objects, but its defining value is the governed business logic that makes those objects consistently queryable.

Precise definition

The semantic layer is a governed, reusable business abstraction over data. A semantic model groups one or more data objects and defines the dimensions, measures, relationships, calculations, metrics, hierarchies, filters, and business context required to query those objects consistently.

StatementVerdictWhy
“It is a data dictionary.”PartlyIt includes labels, descriptions, types, formatting, and business terminology—but also calculations and query behavior.
“It is a group of logical objects.”PartlyA semantic model must contain one or more data objects, but relationships, metrics, dimensions, and measures make the grouping meaningful.
“It is a governed business/query model.”YesThis captures both business meaning and executable analytical behavior.
Salesforce's wordingSalesforce describes semantic models as first-class metadata and “a grouping of Semantic Definitions tailored for a specific analytical use case.” A model must contain one or more data objects.

02 / The layer

It sits between raw data and business questions.

Consumers ask in business language. The semantic layer resolves that language into governed objects, relationships, calculations, filters, and aggregations before the underlying data is queried.

Business language

Rename and enrich

Turn technical fields into understandable concepts and descriptions.

Business logic

Calculate and govern

Define aggregations, formulas, filters, time behavior, and KPI rules once.

Query behavior

Connect correctly

Choose valid relationships and preserve grain when combining objects.

03 / Anatomy

A semantic model is a graph of reusable definitions.

Objects are the foundation, but they become useful only when the model adds descriptive dimensions, numeric measures, relationship paths, runtime calculations, and governed metrics.

01 / NODESData objectsOpportunity, Account, Order, Case, Agent Session
02 / LABELSDimensionsStage, Industry, Region, Quarter, Product Category
03 / FACTSMeasuresAmount, Revenue, Quantity, Duration, Count
04 / EDGESRelationshipsJoin criteria, path, physical/logical type, cardinality
05 / LOGICCalculated fieldsDerived classes, ratios, formulas, runtime calculations
06 / KPIsMetricsOpen Pipeline, Win Rate, Retention, Resolution Time
07 / SHAPESLogical viewsReusable joined objects assembled from multiple tables
08 / CONTEXTPreferences & rulesFiscal calendar, business terminology, filters, overrides, goals

06 / Query time

Business language becomes a governed query plan.

The semantic layer is active at query time. It resolves terms, chooses measures and dimensions, follows relationship paths, preserves grain, applies metric rules, and generates a query against the underlying data.

01 / ASKBusiness question“Pipeline by industry this quarter”
02 / RESOLVEMetricOpen Pipeline definition
03 / MAPDimensionsIndustry + fiscal quarter
04 / CONNECTRelationshipsOpportunity → Account
05 / APPLYLogicStage filter + aggregation
06 / QUERYData 360Governed physical query
07 / RETURNTrusted resultConsistent across consumers

Salesforce exposes Semantic Query and Semantic Metric Query APIs so applications can use this governed layer to answer business questions and calculate metrics.

07 / Relationships and grain

The hardest value is often preventing wrong math.

Relationship metadata includes join criteria and cardinality, and Salesforce describes semantic relationships as connections designed to preserve data granularity.

Correct path

Opportunity → Account

Many opportunities belong to one account. Grouping pipeline by account industry is valid when the model follows this many-to-one path.

Fan-out risk

Opportunity → Products

One opportunity can have multiple products. Summing opportunity amount after joining products can duplicate the opportunity unless grain is handled correctly.

Semantic valueThe layer can encode the valid relationship, cardinality, aggregation behavior, and logical view so each consumer does not rediscover—and potentially mishandle—the join.

08 / Agents

It gives AI a business contract, not just schema.

An agent looking only at columns sees technical possibilities. An agent using a semantic model sees governed business concepts, valid relationships, reusable metrics, and organization-specific preferences.

Without semantics

Schema guessing

  • Which amount field is “revenue”?
  • Which date defines “this quarter”?
  • Which stage values are open?
  • Can Opportunity safely join Products?
  • Should amount be summed or averaged?
With semantics

Governed interpretation

  • Metric identifies the approved revenue/pipeline definition.
  • Business preference identifies the fiscal period.
  • Relationship identifies the valid path and cardinality.
  • Measure identifies aggregation behavior.
  • Descriptions and labels provide business language.

Salesforce's release documentation says Tableau Semantics maps raw data to business-friendly terms and logic to create reusable models and metrics that provide contextual, consistent, trusted insights. Business Preferences add organization-specific context for agent answers.

09 / Boundaries

What the semantic layer is not.

Not the data lake

It usually does not copy every row

It is primarily governed metadata and query behavior over existing data objects.

Not ETL

It does not replace preparation

Source ingestion, harmonization, and identity resolution remain separate concerns.

Not one dashboard

It is reusable

The same definitions can support dashboards, APIs, applications, and agents.

Not semantic search

Different concept

A semantic analytics layer governs business meaning and queries; semantic search retrieves items by meaning.

Not only objects

Edges and logic matter

A list of logical objects without relationship, metric, and aggregation semantics is insufficient.

Not merely documentation

Executable metadata

The query engine can apply definitions at runtime to answer business questions.

Bottom line

Think of it as a governed business graph and query contract: data objects are the nodes, relationships are the edges, dimensions and measures describe behavior, and metrics encode the business outcomes everyone should calculate the same way.
